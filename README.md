# Robot Sim2Real RL Agent

Проект в рамках студкэмпа от Яндекса.
Два робота кооперируются в реальном мире, чтобы найти
и захватить жёлтый мяч. Управляющая политика захватного робота **обучается в
симуляторе Unity (ML-Agents, PPO)** и переносится на реальное железо

---

## Что и где делается

**Трасса**: поле 3 на 4 метра, с блоками (0.2x0.2x0.2 м) в случайной расстановке. Мяч (диаметр 10 см) лежит на полу в открытой зоне на другом конце поля.

**Цель**: Захват роботом **GFS-X** мяча в открытой зоне, после того как скаут его обнаружил и верифицировал.

**Процесс**: Захватный робот **GFS-X** обучается в Unity управлять моторами/манипулятором по входам сенсоров (входной вектор обсуждается далее) и данным с камеры.

---

## Роботы

### Робот-скаут (яндекс мини-ровер)

**ОС**: ROS 2
**Задача**: объехать препятствия, найти мяч (YOLO), верифицировать через удаленную VLM,
**Сенсоры**: камера + лидар, собственная YOLO **локально**

### Робот GFS-X (захватный)

**ОС**: ROS 1 (развернут в Docker)
**База**: Raspberry Pi 4B, гусеничная платформа, `armv7l`
**Задача**: доехать в зону, найти скрытый мяч, захватить манипулятором.
**Сенсоры**:

- камера с поворотом
- Ультразвук привязан к повороту камеры
- ИК-датчики: влево, вправо (препятствия), в манипуляторе (наличие мяча)

## Глава 1. Об обучении и необучаемости

**Технологии**: Unity,  ML-Agents (PPO + LSTM), обучение через python ml-agents на удаленной машинке (16 ядер, 32гб, 100гб диска)

### Наблюдения (observations)

Финальный вектор состоит из **13 значений** (`CollectObservations`), при `NumStackedVectorObservations=4` на вход сети идёт **13 × 4 = 52** (краткосрочная память кадров + LSTM):

### Действия (actions)

**3 непрерывных** действия:

| # | Действие |
| --- | --- |
| 0 | gas (вперёд/назад) |
| 1 | steering (руль влево/вправо) |
| 2 | camera_delta (поворот серво камеры) |

Клешня работает автоматически по ИК-датчику клешни (сеть ей не управляет).

### Система наград

#### Терминальные

| Терм | Значение |
| --- | --- |
| **grabSuccessReward** | **+5.0** |
| **outOfArenaPenalty** | **−2.0** |
| **timeoutPenalty** | **−1.0** |
| **obstacleCollisionPenalty** | **−1.0** |

#### Dense per-step (каждый шаг)

- **2 Phase Distance reward**
  
    *Этап 1*: робот едет к мячу, награда растёт по мере сближения (distance-based reward)

    *Этап 2*: после определенной границы, робот должен замедляться и аккуратно вкатываться в клешню (gentle placement). В противном случае получет штраф за резкость.

- **Штрафы за резкость управления**

  Сглаживают езду и камеру (камера штрафуется сильнее — 
  дёрганье смазывает реальную YOLO).

- **Centering streak** - награда за удержание мяча в центре кадра
  Streak-механика: награда растёт за **непрерывное** удержание, поощряет плавный трекинг.

- **Body-camera alignment** — корпус смотрит куда камера
  Не даёт смотреть камерой вбок, а ехать прямо

- **Wall proximity** — близость стен (бинарно)

- **Per-step penalty**

- **Backward movement**
  против езды задом.

- **Blind approach** — поиск вперёд когда мяч не виден
  Стимул активно ехать/искать.

*Remark*. Этот набор штрафов с заданными параметрами может довольно плохо обучаться, в процессе экспериментов было перебровано много вариантов, так что стоит тьюнить параметры.

### Доменная рандомизация и шумы

Для sim-to-real использовалась Доменная рандомизация, параметры сцены и робота всегда отличались, чтобы не было overfitting под конкретные сценарии.
- `vision_noise`, `ultrasonic_noise` — шум сенсоров
- `sensor_latency`, `action_latency` — задержки ROS-пайплайна (FIFO-буферы)
- `ball_scale`, `ball_mass` — размер/масса мяча (uniform)
- `robot_max_speed_min/max` — макс. скорость робота
- `camera_servo_max_angle` = 20° — камера/УЗ крутятся только ±20°
- `auto_center_camera` — камера к 0 когда мяч не виден (УЗ смотрит вперёд)

### Конфиг обучения

Конфиги обучения могут быть найдены в configs

### Сборка и запуск обучения

Всё монжо запустить через `Makefile`:
```bash
make setup        # venv + mlagents (один раз)
make build        # Unity-билд
make train        # новый run
make resume       # продолжить последний
make tensorboard  # графики
```

Или напрямую:
```bash
mlagents-learn configs/config_final.yaml --run-id=final \
  --env=./Linux_Build/Build.x86_64 --num-envs=2 --no-graphics \
  --env-args -logFile /tmp/unity.log
```

Ступенчатое обучение с переносом весов если используется Curriculum learning:
```bash
mlagents-learn config_stageN.yaml --run-id=stageN --initialize-from=stageN-1
```

## Глава 2. Конфигурация железа

Здесь всё использовалось стандартное, данное от производителя XiaoRGeek (GFS-X). Пины, константы и драйверы — в `Robot/config.py` и `Robot/xr_gpio.py`.

### Запуск через Unity (ROS-мост)

`unity_master_team2.py` — ROS-нода: принимает `/cmd_vel` (Twist) от Unity через ROS-TCP,
раскладывает в дифференциальный PWM, публикует сенсоры (`/sensor/data`), управляет серво.
Есть CSV-логирование в `/tmp/unity_logs/`.

```bash
./start_robot_team2.sh   # roscore + ros_tcp_endpoint + unity_master + gripper_ir
```

## Глава 3. Глаза и связь

Скрипт `yolo_vision_node.py` используется на ноуте, так как 4ая малина слишком слаба для запуска YOLO + трекинга.
Скрипт: 
- Читает MJPEG-стрим камеры GFS-X (`http://<gfsx>:8080`)
- `model.track()` (BoT-SORT/ByteTrack) — детекция + трекинг мяча
- Шлёт UDP JSON на `<gfsx>:5005`: `{angle, distance, sees, conf, w, h}`

`camera_stream_team2.py` (на **хосте** Pi): MJPEG-сервер :8080
